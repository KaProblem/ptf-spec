# PTF figure

A figure is one SVG file that a host shows as a card and reveals step by
step while the tutor talks (SPEC.md §6.8 in ptf-spec has the rules). The
tutor never sees the picture, only its `<desc>` and step captions, so the
words matter as much as the drawing.

## 1. Plan in words first

- Is a figure the right medium? Use one when the learner would otherwise
  build the picture in their head (a graph, a shape, quantities side by side,
  a construction or proof). If they should change something and watch the
  result, that is a simulator; a single fact needs no picture.
- One idea per figure. Name the objective (or misconception) it serves.
- Write `<title>`, `<desc>` and the step captions **before** any drawing:
  what the learner should see, in which order, with the numbers. Three to
  six steps; step 1 already shows something; the last step states the point.
  Captions are full sentences a learner can read without the tutor.

## 2. Draw it with a script

Compute every coordinate in a small script (Python or Node), never by eye,
and keep it as `figures/src/<id>.py` (or `.mjs`) in the bundle so the figure
can be regenerated and its numbers checked. The script MUST compute every
number that appears in a label or in `<desc>` from the same values it draws
with, and assert the facts the figure claims (e.g. `assert f(2) / f(1) == 1.5`).
Physics follows SIMULATOR-SPEC.md §8.5.

Skeleton:

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 340 300" role="img" aria-labelledby="ID-t ID-d" data-ptf-figure="1">
  <title id="ID-t">…</title>
  <desc id="ID-d">…</desc>
  <defs><marker id="ptf-arrow-ink" viewBox="0 0 10 10" refX="9" refY="5" markerWidth="6" markerHeight="6" orient="auto-start-reverse"><path class="f-ink" d="M0 0 L10 5 L0 10 z"/></marker></defs>
  <g><!-- always visible: axes, grid, ticks --></g>
  <g data-step="1" data-caption="…">…</g>
</svg>
```

Rules that keep it readable and safe (`ptf-check` enforces them):

- viewBox at most **360 units wide**; text classes `t` (16), `t-s` (14),
  `t-l` (20); nothing smaller. Leave 10 units of margin for labels.
- Colours only through classes: `s-ink s-muted s-line s-accent s-warn s-good`
  (stroke), `f-ink f-muted f-surface f-accent f-warn f-good f-accent-soft
  f-warn-soft f-good-soft f-none` (fill), `w1 w2 w3`, `dash`, `math`, `bold`.
  Accent = what the step is about, warn = the thing to notice, good = the
  result; grid in `s-line`, axes in `s-ink`.
- One arrow marker per colour (`ptf-arrow-ink`, `-accent`, `-warn`, `-good`)
  in `<defs>`, with a `f-` class on its path.
- No `<script>`, `<style>`, `<image>`, `<foreignObject>`, links, `style` or
  font attributes, animations.
- Formulas in Unicode (½, ², √, π, ·, −, ×, →), not LaTeX. Variables in `math`.

## 3. Screenshot check (mandatory)

```bash
node ../ptf-spec/tools/ptf-figure.mjs check bundles/<bundle>/figures/<id>.svg
node ../ptf-spec/tools/ptf-figure.mjs shot bundles/<bundle>/figures/<id>.svg --out /tmp/figure-shots
```

`shot` renders the card at 320 px (every step, light and dark) and 640 px,
reports text that overlaps other text or leaves the viewBox and the smallest
text size on a phone. Then **open and look at every PNG yourself**; the tool
cannot see most faults. In the first rounds expect these:

- text too small because the viewBox is too wide;
- a label lying on a line, a point or another label;
- an arrowhead missing or pointing the wrong way;
- something invisible in dark mode (a fill without a class);
- a step that shows nothing new, or reveals the answer too early;
- a legend or formula squeezed against the edge.

Fix, regenerate, look again until nothing is left. A figure is not done
until you have looked at the final 320 px screenshots, light and dark.

## 4. Translations

A translation is `figures/<id>.<lang>.svg`, generated by the same script
with other words: same steps, same coordinates, decimal commas where the
language uses them. Run the screenshot check on it too: German labels are
longer.

## 5. Wire it up

- List it in the element: `figures: [{ id, objectives: [...], use_when: "…" }]`,
  bump the element's minor version, and mention in `# Tutor notes` if the
  author wants it shown at a particular moment.
- `node ../ptf-spec/tools/ptf-check.mjs .` (0 errors) and
  `node ../ptf-spec/tools/ptf-check.mjs catalog --write .`.
- Show the user the 320 px screenshots (light and dark) when you report.
